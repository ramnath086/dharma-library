# Dharma Library — Flutter app

Platform folders here are intentionally minimal (manifest, Info.plist, Gradle
config, deep-link + audio permissions). On first checkout run:

```bash
cd app
flutter create . --platforms=android,ios --org org.dharmalibrary --project-name dharma_library
```

`flutter create .` regenerates the boilerplate files (icons, LaunchScreen,
Runner.xcodeproj, gradle wrapper jar) **without overwriting** the files
committed here. Then:

```bash
flutter pub get
flutter gen-l10n
flutter test
flutter run --dart-define-from-file=../env.json     # or --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

Without `SUPABASE_URL`/`SUPABASE_ANON_KEY` the app runs in **bundle mode**:
content comes from every JSON file in `assets/bundles/` (currently the
Bhāgavata and the Bhagavad Gītā, generated by `scripts/export_bundle.py`).
The Flutter asset manifest discovers these works dynamically; bookmarks/progress
stay on-device, and Ask/Sign-in are disabled.


## Android Gradle files
`android/settings.gradle`, `android/build.gradle`, `android/app/build.gradle` and the
Gradle wrapper are **not committed** — `flutter create . --platforms=android` generates
versions matching your Flutter SDK. Committed customisations: `AndroidManifest.xml`
(deep link, audio permissions), `proguard-rules.pro`, `res/values/styles.xml`,
`MainActivity.kt`. For release signing, add `android/key.properties` + keystore
(git-ignored) and wire `signingConfigs` per Flutter docs.
